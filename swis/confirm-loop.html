3. ขอบเขตข้อมูล 5 หมวด · พร้อมแหล่งที่มา

ฟอร์มยืนยันแสดงข้อมูล 5 หมวด — ทุกช่องในฟอร์มจะมี ป้ายกำกับ ว่าข้อมูลดึงมาจาก SWIS module ใด ตารางใด ครั้งล่าสุดเมื่อไหร่ และโดยใคร — เพื่อให้หัวหน้าหน่วยงานรู้ว่า ถ้าต้องแก้ ต้องไปแก้ที่ไหน

หมวด สิ่งที่ต้องตรวจ ระบบดึงข้อมูลมาจาก
1. บุคลากร รายชื่อในหน่วยงาน · ตำแหน่ง · อัตรากำลัง · สถานะปัจจุบัน SWIS → HR module ตาราง employee + assignment
2. Job Spec C/K/Cp สมรรถนะที่ผูกกับแต่ละคน — Core (C) · Knowledge (K) · Competency (Cp) รวม 137 หัวข้อ SWIS → Job Spec module — ที่หน่วยงานทยอยกรอกตั้งแต่ปีก่อน
3. โครงสร้าง ผังหน่วยงาน · สายบังคับบัญชา · คำสั่งแต่งตั้งล่าสุด SWIS → Org Chart module + คำสั่งแต่งตั้ง (ฝ่าย HR upload)
4. ทรัพย์สิน อุปกรณ์ · ครุภัณฑ์ · สถานะการใช้งาน SWIS → Asset module (ฝ่ายพัสดุ + ICT4 บันทึก)
5. สถานะแผน PDCA 9 แผนงาน 9 ขั้น · KPI · งบประมาณ · ตัวชี้วัด SWIS → Plan module ตาม คู่มือ PDCA 9 ฉบับมูลนิธิฯ v1
หมายเหตุสำคัญเรื่องความโปร่งใสของช่องข้อมูล: ทุกช่องในฟอร์มยืนยันจะมีป้ายกำกับเล็ก ๆ บอกว่า ดึงจาก SWIS module ใด · ตารางใด · กรอกครั้งล่าสุดเมื่อไหร่ · โดยใคร — หากท่านพบว่าข้อมูลไม่ตรง จะทราบทันทีว่า "ใครต้องไปแก้ที่ไหน" โดยไม่ต้องสอบถาม

4. กระบวนการดำเนินการ — สำหรับหัวหน้าหน่วยงานและทีม

6 ขั้นตอน · ออกแบบให้ทำได้ภายใน 2 สัปดาห์ก่อนเปิดเทอม

0

เตรียมตัว 1 วัน

หัวหน้าหน่วยงาน login เข้า SWIS → เปิด Dashboard "Confirm Loop 2569" → จะเห็นรายการ 5 หมวดของหน่วยงานตน

1

Review ข้อมูล auto-fill 2–3 วัน

เข้าทีละหมวด — ระบบดึงข้อมูลมาให้แล้วทั้งหมด ไม่ต้องกรอกใหม่ แค่ตรวจ

  • ดูป้ายกำกับว่าข้อมูลแต่ละช่องดึงจากไหน · กรอกครั้งล่าสุดเมื่อไหร่
  • เปรียบเทียบกับสภาพจริงของหน่วยงาน ณ ปัจจุบัน
  • ทำเครื่องหมายไว้ก่อน — ยังไม่ต้องกดยืนยัน
2

แบ่งงานในทีม 1 วัน

หัวหน้ามอบหมายแต่ละหมวดให้สมาชิกทีม + กำหนด deadline ภายในทีม (เร็วกว่า deadline ส่วนกลาง 2 วัน)

3

กรอกผลการตรวจ 3 วัน

แต่ละรายการเลือก 1 ใน 3 สถานะ:

  • ยืนยัน — ระบบ stamp timestamp + login = ผูกพันรับทราบ
  • ขอแก้ไข — ระบุจุดผิด + ข้อมูลที่ถูกต้อง + วันแก้เสร็จ + ผู้รับผิดชอบ
  • ขาด — ระบุว่าจะเติมเมื่อไหร่ + ใคร
4

ทีมแก้ไข 5–7 วัน

ดำเนินการแก้ตามที่ระบุไว้:

  • แก้ใน SWIS โดยตรง (ถ้าหน่วยงานทำได้)
  • ส่ง ticket ทีมส่วนกลาง (ถ้าต้อง support)
  • ทีมส่วนกลางช่วยให้ — แต่ deadline ยังเป็นของหน่วยงาน
5

Confirm รอบสุดท้าย 1–2 วัน

หลังแก้แล้ว → กดยืนยันอีกครั้ง → Dashboard แสดง 100% green = หน่วยงานพร้อม → ส่งรายงานสรุปอัตโนมัติให้ ผอ. + ฝ่าย ICT มูลนิธิฯ

6

เปิดเทอม 16 พ.ค. 2569

เริ่มงานด้วยข้อมูลที่ "ยืนยันแล้ว" ทั้งหมด — ทุก PDCA, KPI, งบประมาณ มี baseline ที่หน่วยงานรับรองเอง · เอนจิ้นพร้อมสตาร์ท

6. หลักการสำคัญ

ระบบไม่ได้ขอข้อมูลใหม่ — ระบบขอให้หัวหน้าหน่วยงานยืนยันสิ่งที่ทีมหน่วยงานกรอกไว้แล้วใน SWIS

กดยืนยัน = ผูกพันรับทราบ — มี timestamp + login = หลักฐาน digital

ก่อนเปิดเทอม = บีบเวลาให้พร้อม · ข้อมูลที่ยืนยันแล้ว = ฐาน PDCA, KPI, งบประมาณทั้งปี

7. คำถามที่พบบ่อย

ถ้าไม่กดยืนยันภายในกำหนดจะเป็นอย่างไร?

ระบบจะใช้ Hybrid Mode — ถือว่ายืนยันอัตโนมัติเมื่อพ้นกำหนด (Silent Approval) แต่ส่ง escalate ขึ้น ผอ. + ฝ่าย ICT มูลนิธิฯ พร้อมระบุว่าหน่วยงานใดยังไม่ได้กดยืนยัน — เพื่อไม่ให้งาน block แต่ผู้บังคับบัญชาทราบ

ถ้าข้อมูลใน SWIS ไม่ตรงกับสภาพจริง — ทำอย่างไร?

กด "ขอแก้ไข" → ระบุจุดผิด + ข้อมูลถูกต้อง + วันแก้เสร็จ → แก้ใน SWIS (เองหรือผ่านทีมส่วนกลาง) → กดยืนยันใหม่ → ปิด loop

ถ้าหัวหน้าหน่วยงานติดภารกิจ — มอบให้คนอื่นทำได้ไหม?

ทีมในหน่วยงานช่วยตรวจและกรอกได้ — แต่ การกด "ยืนยัน" ต้องเป็นหัวหน้าหน่วยงาน login ด้วยตนเอง เพื่อให้ timestamp + signature ถูกต้องตามหลักธรรมาภิบาล

ทำไมต้องทำก่อนเปิดเทอม?

ข้อมูลที่ยืนยันแล้ว = ฐานในการวางแผน PDCA, ตั้ง KPI, จัดงบประมาณ ตลอดทั้งปี — ถ้าฐานไม่นิ่ง ทุกอย่างที่ตามมาก็ไม่นิ่ง · กระทบเกณฑ์ธรรมาภิบาล 5.1, 5.2, 3.1

ทำไมหน้านี้อยู่บน fsgthailand.org แทนที่จะเป็น swisplus.com?

กระบวนการ Confirm Loop เป็นนโยบายของ มูลนิธิคณะเซนต์คาเบรียลฯ ในฐานะผู้กำกับนโยบาย — ไม่ใช่ของบริษัท SWIS Plus ในฐานะผู้พัฒนาระบบ การวางที่นี่ทำให้ความรับผิดชอบและอำนาจชัดเจน
